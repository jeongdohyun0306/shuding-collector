# 한국어 조건 사진 검색: 슈딩이 컬렉터 v2

한국어 문장으로 사진을 찾는 검색 기술을 개선한다. 특히 "안경을 안 쓴 슈딩이", "사람 없이 밖에 있는 사진"처럼 무언가를 빼라는 조건을 다룬다. 출발점은 발표 자료 "슈딩이 컬렉터"(`Introducing Schding Collector.pdf`)가 설명한 방식(v1)이다. v1을 발표 설명대로 재현해 두고, 같은 정답표로 개선한 방식(v2)과 비교했다. 저장소는 검색 방법의 구현(`sc/`), 평가용 사진·라벨·색인(`data/`, `index/`), 채점 코드와 검색어(`bench/`), 채점 결과(`results/`)로 되어 있다.

## 풀려는 문제

v1은 사진과 검색어를 EmbeddingGemma 2로 같은 768차원 공간에 넣고 코사인 유사도로 순위를 매긴다. 이 계산에는 부정이 들어갈 자리가 없다. "안경을 안 쓴 슈딩이"의 벡터는 "안경"이라는 단어에 끌려 안경 쓴 사진 쪽으로 간다. 평가 사진 301장에서 v1로 이 검색어를 찾으면 1위와 2위가 안경을 쓴 슈딩이 사진이다. 벤치마크의 부정 검색어 12개에서 v1 상위 10장 중 24.2%가 금지 조건을 어긴 사진이었다.

원본의 검색어 전처리는 내용을 알 수 없어서, v1에는 "슈딩이"를 "고양이"로 바꾸는 처리만 넣었다. v2도 이름은 똑같이 처리한다.

## 방법

v2는 원본 발표가 이미 쓰던 두 모델(EmbeddingGemma 2, Qwen3-VL-2B-Instruct)만 쓴다. 검색할 때 도는 모델은 v1과 같은 EmbeddingGemma 2 하나이고, Qwen3-VL-2B는 색인할 때만 돈다. 최종 구성값은 `sc/v2.py`의 `FINAL`에 있다.

### 1. 사진 설명 융합

색인할 때 Qwen3-VL-2B가 사진마다 영어 설명을 쓰고(프롬프트는 짧은 3문장을 요청한다, `sc/vlm.py`), 그 설명도 EmbeddingGemma 2로 임베딩한다. 한국어 검색어를 이 영어 설명과 번역 없이 그대로 비교한다. 검색 문장 t와 사진 x의 점수는 사진 유사도와 설명 유사도를 각각 표준화해서 더한 값이다.

```
s(t, x) = z(cos(t, 사진 x)) + z(cos(t, 설명 x))
```

z는 검색 문장 하나에 대해 사진 전체의 점수를 평균 0, 표준편차 1로 맞춘다.

### 2. 한국어 부정 분해 (`sc/kparse.py`)

검색어를 찾을 문장 하나와 뺄 문장 여러 개로 나눈다. Kiwi 형태소 분석기의 품사 태그로 아래 다섯 갈래의 부정 구문을 찾는다.

| 구문 | 검색어 | 찾을 문장 | 뺄 문장 |
|---|---|---|---|
| 안·못 + 용언 | 안경을 안 쓴 슈딩이 | 고양이 | 안경을 착용한 고양이 |
| ~지 않·못하·말 | 모자를 쓰지 않은 슈딩이 | 고양이 | 모자를 착용한 고양이 |
| 없·없이 | 사람 없이 밖에 있는 사진 | 밖에 있는 사진 고양이 | 사람과 함께 있는 고양이 |
| 아니 | 실내가 아니라 밖에서 누워 있는 슈딩이 | 밖에서 누워 있는 고양이 | 실내에 있는 고양이 |
| 말고·빼고·제외하고 | 소파 말고 침대에 누운 슈딩이 | 침대에 누운 고양이 | 소파에 있는 고양이 |

용언이 부정되면 부정을 뗀 문장이 뺄 문장이 된다("밥을 안 먹는"은 "밥을 먹는 고양이"). 다만 착용 동사(쓰다, 입다, 끼다 등)는 "~을 착용한 고양이"로 묶는다. 없·아니·말고·빼고·제외하고로 빠진 명사는 부류에 따라 틀을 고른다. 사람과 동물은 "~와 함께 있는 고양이", 장소는 "~에 있는 고양이", 착용품은 "~을 착용한 고양이"다. 형태소 단위로 보기 때문에 "안경안쓴슈딩이"처럼 붙여 써도 같은 결과가 나오고, "상자 안에", "편안하게", "쉴 새 없이"는 부정으로 읽지 않는다. "사람이나 다른 고양이, 강아지 없이"처럼 나열한 대상은 셋 다 뺀다. 이런 경우들은 `tests/test_kparse.py`에 회귀 시험으로 있다.

처음에는 Qwen3-VL-2B에게 분해를 맡겼는데, '모자 안 쓰고'를 모자 쓴 고양이를 찾는 뜻으로 뒤집어서 규칙으로 바꿨다(이 시험의 출력은 저장소에 남기지 않았다). 다음에 쓴 공백 기준 규칙은 감사용 새 표현 87개 중 감사자 판정으로 36개, 감사자가 적은 기대값과 글자까지 같은 것으로는 24개를 맞혔다. 형태소 기반인 지금은 같은 글자 기준으로 66개다(`bench/parser_stress.py`, 원자료 `bench/audit/parser_stress.json`). 지금 분해기는 이 87개의 실패 유형을 보고 고친 것이라, 66은 처음 보는 문장에 대한 성적이 아니다.

### 3. 부정 감점

뺄 문장 n마다 같은 방식으로 점수를 매기고, 그 점수가 τ를 넘는 만큼 뺀다.

```
score(q, x) = s(찾을 문장, x) - λ · Σ_n max(0, s(n, x) - τ)
```

λ = 1, τ = 1이다. 뺄 문장에 대한 사진 쪽과 설명 쪽 표준화 점수의 합이 1을 넘는 사진부터, 넘은 만큼 깎는다. 두 값은 설명 융합 없이 사진 유사도만 쓴 구성(아래 표의 "+ 부정 감점" 줄)에서 벤치마크 dev 검색어로 골랐다(`results/summary.json`의 `penalty_grid_dev`). v2 점수로 같은 3 × 4 격자를 돌리면 dev nDCG@10이 0.887에서 0.891 사이이고, λ = 1, τ = 1은 0.890으로 가장 높은 칸(λ = 1 또는 2, τ = 2)과 0.001 차이다(`penalty_grid_dev_v2`). 그래서 값을 바꾸지 않았다.

## 구성요소별 기여

벤치마크 47개(dev 24, test 23)의 nDCG@10이다. 부정 위반은 부정 검색어 12개에서 상위 10장 중 금지 조건을 어긴 사진 비율이다. 두 지표 모두 그 검색어로는 정답 여부를 판정할 수 없는 사진('?' 라벨)을 순위에서 빼고 센다.

| 구성 | 전체 | test | 부정 12개 | 부정 위반 |
|---|---|---|---|---|
| 사진 유사도만 (v1과 같은 순위) | 0.735 | 0.689 | 0.505 | 24.2% |
| + 부정 분해 | 0.810 | 0.761 | 0.800 | 11.7% |
| + 부정 감점 | 0.817 | 0.772 | 0.826 | 4.2% |
| + 사진 설명 융합 (v2) | 0.862 | 0.833 | 0.886 | 2.5% |
| 설명 융합만, 분해 없이 | 0.764 | 0.715 | 0.502 | 30.8% |

부정 검색어에서 오른 0.381 중 77%가 분해, 7%가 감점, 16%가 설명 융합에서 나왔다. 단일·복합 조건 검색어에서는 분해와 감점이 하는 일이 없어서, 오른 몫이 전부 설명 융합에서 나온다. 분해 없이 설명만 더하면 부정 위반이 24.2%에서 30.8%로 오히려 늘어난다.

EmbeddingGemma 2 벡터를 앞쪽 차원만 남겨 줄이면 전체 nDCG@10이 768차원 0.862, 512차원 0.850, 256차원 0.839, 128차원 0.727이다.

## 버린 방법

| v2에 더한 것 | dev | test | 전체 |
|---|---|---|---|
| (v2) | 0.890 | 0.833 | 0.862 |
| Qwen3-VL-Embedding-2B 사진 유사도 | 0.904 | 0.828 | 0.867 |
| Qwen3-VL-Reranker-2B로 상위 30장 재정렬 | 0.903 | 0.816 | 0.861 |
| 상위 30장에 Qwen3-VL-2B로 뺄 조건 예/아니오 확인 | 0.890 | 0.830 | 0.861 |
| 같은 확인을 찾을 조건까지 | 0.894 | 0.845 | 0.870 |
| Qwen3-VL-2B로 검색어를 영어로 옮겨 같이 검색 | 0.907 | 0.813 | 0.861 |

dev에서 v2보다 높은 구성도 차이가 0.02 이내였다. 그런데 모두 검색할 때 모델을 하나 더 GPU(8GB)에 올리거나 검색마다 Qwen3-VL-2B를 돌려야 한다. test에서는 찾을 조건 확인만 v2보다 0.012 높았고 나머지는 낮았다. Qwen3-VL-2B 번역은 "안긴 고양이"를 "Closed cat"으로, "사람한테 안긴 고양이"를 "Cat I put in a person's pocket"으로 옮기는 식으로 틀리기도 한다(`index/query_cache.json`의 `tr|` 항목). 예/아니오 확인 두 줄도 한국어 문장을 이 번역으로 옮긴 뒤 묻는다. 그래서 검색 때 모델 하나로 끝나는 v2를 골랐다.

## 결과 (nDCG@10, 높을수록 좋음)

| 검색어 묶음 | 개수 | v1 | v2 | 차이 95% 신뢰구간 |
|---|---|---|---|---|
| 처음 보는 검색어 (2차 held-out) | 44 | 0.486 | 0.685 | +0.136 ~ +0.265 |
| 그중 부정 조건 | 35 | 0.461 | 0.679 | |
| 벤치마크 전체 | 47 | 0.735 | 0.862 | +0.078 ~ +0.182 |
| 벤치마크 단일 조건 | 25 | 0.850 | 0.879 | +0.004 ~ +0.054 |
| 벤치마크 복합 조건 | 10 | 0.721 | 0.792 | +0.022 ~ +0.122 |
| 벤치마크 부정 조건 | 12 | 0.505 | 0.886 | +0.279 ~ +0.471 |

부정 위반은 처음 보는 검색어에서 28.0%에서 9.7%로 줄었다. 질의 시간 중앙값은 단일·복합 조건에서 v1과 거의 같고(44~47 ms), 무언가를 빼는 검색에서는 v2가 뺄 문장을 한 번 더 임베딩해서 46 ms에서 92 ms로 약 두 배가 된다(RTX 5060 노트북, `results/summary.json`의 `latency_ms`). 같은 컴퓨터에서도 잴 때마다 10 ms 안팎으로 달라진다.

조건 종류별·부정 형태별·실사진 13장 분석은 `bench/breakdown.py`(결과 `results/breakdown.json`, 분해기를 고치기 전 판으로 냈다), 그 주장들의 독립 반박 검증은 `bench/audit/claims_verification.json`에 있다(라벨을 고치기 전 수치로 검증했다). 2026-10-20에 실사진 2장의 "사람" 라벨 누락을 고쳤고, 고치기 전 결과는 `results/*_before_label_fix.json`이다.

정답 라벨은 사람이 아니라 Claude(AI)가 사진을 한 장씩 보고 붙였다. 다른 Claude 에이전트가 101장을 따로 라벨링해서 대조한 코드 단위 일치율은 98.1%다. 벤치마크 검색어와 부정 분해기를 같은 작성자(Claude)가 만들었기 때문에 벤치마크 수치는 부풀려져 있을 수 있다. 처음 보는 검색어 줄이 더 믿을 만한 숫자다. 이 검색어는 분해기 코드를 고정(`bench/FROZEN_ENGINE_SHA256.txt`)한 뒤 코드를 본 적 없는 에이전트 셋이 썼고, 다른 에이전트가 문장 뜻과 정답식이 맞는지 검사해서 56개 중 12개를 뺐다.

### 고정 이후 분해기 수정 (2026-10-20)

위 표의 처음 보는 검색어 0.685는 분해기를 고정한 판(커밋 0b8196e)의 결과다. 그 44개에서 v2가 v1보다 진 5개 중 4개가 분해기 오류였고(범위 오류 3개, "다른 데서" 처리 1개), 이를 고쳤다.

- 관계절 뒤의 "사진/모습 빼고·말고": "사람 품이나 무릎에 있는 사진 빼고"에서 "사진"만 빼던 것을 관계절까지 뺀다.
- 나열: "사람이나 다른 고양이, 강아지 없이"에서 마지막 "강아지"만 빼던 것을 셋 다 뺀다. 쉼표는 양쪽 명사가 같은 부류(사람·동물, 착용품, 장소)일 때만 나열로 본다.
- "다른 고양이는 안 보이는": "다른 고양이"가 부정 범위에서 빠지던 것을 고쳐 "다른 고양이와 함께 있는 고양이"를 뺀다.
- "말고 다른 데서"의 "다른"이 찾을 문장에 남던 것을 지운다.

고친 판으로 44개를 다시 채점하면 0.758(v1 대비 +0.272, 39개 나아짐, 1개 나빠짐), 부정 위반 3.4%다. 다만 점수가 바뀐 검색어 6개는 전부 고칠 때 들여다본 것이고 나머지 38개는 점수가 소수점까지 같다. 그래서 이 수치는 처음 보는 검색어 결과로 볼 수 없다. 벤치마크 47개는 분해 결과가 하나도 바뀌지 않아 점수가 같다. 결과는 `results/heldout2_after_fix.json`에 있다.

## 한계

- 평가 사진 301장 중 실제 슈딩이 사진은 발표 자료에서 꺼낸 13장뿐이고 나머지 288장은 COCO 고양이 사진이다. 원래 슈딩이 사진 298장으로는 아직 재지 않았다.
- 처음 보는 검색어 44개 중 24개는 벤치마크 검색어와 정답식이 같다(바꿔 말하기 17개 포함).
- 자세·행동을 찾을 조건으로 가진 처음 보는 검색어 11개는 0.371에서 0.441로 올랐지만 신뢰구간(-0.019 ~ +0.161)이 0을 포함한다.
- 감점이 정답 사진까지 깎는 경우가 있다. "하품하지 않고 입을 벌려 이빨이 보이는 슈딩이"는 분해가 맞지만, 정답 사진 7장 모두 "하품하는 고양이" 점수가 감점 기준을 넘는다. 이 검색어는 v1 0.289, v2 0.220이다.
- 분해기가 못 하는 문장이 남아 있다. "밖에서 찍은 사진 빼고"는 "밖에서"를 뺄 범위에 넣지 못해 "찍은 고양이"를 뺀다. 이름과 동사를 붙여 쓴 "슈딩이자는 사진"은 "고양이자는 사진"이 되어 v1, v2 모두 0점이다.

```
uv venv --python 3.12 .venv
uv pip install --python .venv/Scripts/python.exe "torch==2.14.1+cu130" torchvision --index-url https://download.pytorch.org/whl/cu130
uv pip install --python .venv/Scripts/python.exe transformers sentence-transformers accelerate qwen-vl-utils pillow pillow-heif numpy pymupdf pandas fastparquet kiwipiepy
```

torch를 설치한 뒤 다른 패키지를 `-U`로 올리면 CPU판 torch로 덮어써지니 주의. 색인과 검색 모두 CUDA GPU가 필요하다(`sc/models.py`가 모델을 cuda에 올린다). 확인한 환경은 RTX 5060 8GB다.

## 엔진 쓰기

사진 폴더 색인(아이폰 HEIC도 읽는다):

```
.venv/Scripts/python.exe -m sc.build --photos "D:/슈딩이 사진" --out index_shuding
```

검색어를 넣으면 분해 결과와 순위를 출력한다. `--v1`을 붙이면 원래 방식의 순위도 같이 낸다. `--json`은 같은 내용을 JSON으로 낸다. 기본 이름은 "슈딩이"이고, 다른 고양이는 `--name 나비`처럼 주며 여러 이름이면 `--name`을 반복한다. `--index`를 빼면 평가용 301장 색인(`index/`)을 쓰는데, 이때는 아래 `tools/fetch_coco.py`로 COCO 사진을 먼저 받아야 한다.

```
.venv/Scripts/python.exe -X utf8 -m sc.search --index index_shuding --k 10 --v1 "안경을 안 쓴 슈딩이"
.venv/Scripts/python.exe -X utf8 -m sc.search --index index_nabi --name 나비 "모자 쓰지 않은 나비"
```

파이썬에서는 이렇게 부른다.

```python
from sc.search import load

corpus, engine = load("index_shuding")
engine.parse("안경을 안 쓴 슈딩이")
scores = engine.scores(["안경을 안 쓴 슈딩이"])[0]
```

`engine.parse`는 `{"pos": "고양이", "neg": ["안경을 착용한 고양이"]}`를 돌려주고, `scores`는 `corpus.items` 순서대로 사진마다 점수를 하나씩 준다.

## 평가 재현

COCO 고양이 사진 288장은 저장소에 넣지 않았다. 아래 첫 명령이 `data/coco_meta/chosen.json`에 적힌 주소에서 같은 사진을 받아 `data/coco_photos/`에 둔다. 사진 임베딩과 설명(`index/`)은 저장소에 들어 있어서, 사진을 받으면 GPU로 다시 색인하지 않아도 채점할 수 있다. 사진이 하나라도 없으면 색인을 지우지 않고 멈춘다.

```
.venv/Scripts/python.exe tools/fetch_coco.py
.venv/Scripts/python.exe bench/report_all.py
.venv/Scripts/python.exe bench/heldout2.py bench/audit/heldout2_workflow.json
.venv/Scripts/python.exe bench/agreement.py bench/audit/blind_labels.json
.venv/Scripts/python.exe bench/parser_stress.py
.venv/Scripts/python.exe tests/test_kparse.py
```

`report_all.py`는 벤치마크, 구성 11개(위 두 표와 Qwen3-VL-Embedding만 쓴 구성), 감점 격자 두 개, 1차 held-out, 논란 라벨 제외, 벡터 차원 줄이기, 질의 시간을 한 번에 다시 내고 `results/summary.json`에 쓴다. `parser_stress.py`는 분해기 감사 87개의 맞힌 수를 낸다. `heldout2.py`는 지금 코드의 결과를 `results/heldout2_after_fix.json`에 쓴다. 고정 판의 `results/heldout2.json`을 다시 내려면 `git checkout 0b8196e -- sc/kparse.py`로 분해기를 되돌린 뒤 마지막 인자로 `heldout2.json`을 준다.
